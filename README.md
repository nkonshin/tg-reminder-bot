# tg-reminder-bot

Telegram-бот-напоминалка поверх одного личного диалога в Telegram Business.

## Что это

Бот слушает один конкретный диалог в Telegram Business (открытый на аккаунте
владельца), ловит в нём русские сообщения вида «напомни ...» от одного заранее
заданного человека, сохраняет напоминание в SQLite, пингует адресата в личном
чате с ботом до подтверждения и параллельно создаёт событие в расшаренном
iCloud-календаре по CalDAV. LLM нигде не используется — разбор даты и времени
полностью основан на правилах.

Возможности:

- Триггерные фразы: «напомни», «не забудь», «поставь напоминание» — с допуском
  к опечаткам (fuzzy-сравнение по основе слова, расстояние Дамерау—Левенштейна 1).
- Части суток по умолчанию: утром — 09:00, днём — 14:00, вечером — 20:00
  (настраивается).
- Если время не удалось определить — переспрос в личке с кнопками
  **Утром / Днём / Вечером / Напишу время / Отменить**.
- Карточка о созданном напоминании с кнопками **Отменить / Изменить время**.
- Допинывание каждые 30 минут, максимум 3 раза, с кнопками
  **Готово / Отложить на час**.
- Событие в календаре с будильником (VALARM) на момент начала.

## Как это работает

- `trigger.py` — определяет, содержит ли сообщение триггерную фразу, и вырезает её.
- `parsing.py` — извлекает дату/время и заголовок напоминания из оставшегося текста.
- `flow.py` — вся бизнес-логика (создание напоминания, обработка колбэков, тик
  планировщика). Не знает про типы aiogram, полностью покрыт юнит-тестами на фейках.
- `handlers.py` / `main.py` — тонкая обвязка поверх `flow.py`: aiogram-роутер и
  точка входа (`python -m src.main`), long polling, включая `business_message`.
- `db.py` — состояние в SQLite (файл `DB_PATH`), переживает рестарт процесса.
- `calendar_client.py` — сторонний эффект №2: создание/удаление событий в
  iCloud-календаре через CalDAV.

Планировщик — обычный `asyncio`-цикл в `flow.py`: раз в 30 секунд (`TICK_SECONDS`)
проверяет в SQLite просроченные напоминания и рассылает пинги. Отдельного
джоб-раннера нет — вся нужная информация уже в базе, поэтому рестарт ничего
не теряет.

## Настройка

1. **BotFather**: `/newbot` → получить токен. Затем в том же боте
   `/mybots` → выбрать бота → **Bot Settings → Business Mode → On**.
   Без этого шага бот не увидит сообщения в диалоге Telegram Business.
2. **Подключение к диалогу** (на аккаунте владельца бота, нужен Telegram
   Premium): Настройки → **Telegram Business → Чат-боты** → выбрать бота →
   область видимости «только выбранные чаты» → отметить **только** тот один
   диалог, из которого должны ловиться напоминания. Не давайте боту доступ ко
   всем чатам.
3. **Адресат должен один раз открыть бота и нажать `/start`** в его личном
   чате. Без этого Telegram не позволит боту написать ей первым — сообщения
   не дойдут вообще.
4. Клонировать репозиторий, создать окружение и поставить зависимости:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

5. Скопировать шаблон конфига и заполнить его:

   ```bash
   cp .env.example .env
   ```

   - `BOT_TOKEN` — токен из шага 1.
   - `HER_USER_ID`, `ADMIN_USER_ID` — числовые Telegram ID адресата напоминаний
     и админа (получателя алертов). Узнать свой/чужой ID можно через
     `@userinfobot`.
   - `DIALOG_CHAT_ID` — необязательная дополнительная проверка поверх шага 2
     (область видимости бота в Telegram Business): если задана (не 0),
     сообщения из любого другого бизнес-чата игнорируются в коде, а не только
     на стороне Telegram. Для диалога один-на-один это тот же самый ID, что и
     `HER_USER_ID`; по умолчанию 0 — проверка выключена.
   - `TIMEZONE` — таймзона для отображения и разбора времени, по умолчанию
     `Asia/Yekaterinburg`.
   - `APPLE_ID` / `APPLE_APP_PASSWORD` — Apple ID владельца бота и
     app-specific пароль к нему: account.apple.com → Sign-In and Security →
     App-Specific Passwords → сгенерировать. Обычный пароль Apple ID здесь не
     подойдёт.
   - `CALENDAR_NAME` / `CALENDAR_URL` — целевой календарь. Он должен быть
     заранее расшарен владельцу бота **с правом редактирования**.
6. Определить `CALENDAR_URL`: после заполнения Apple-креденшелов в `.env`
   запустить

   ```bash
   python scripts/list_calendars.py
   ```

   Скрипт печатает все календари, видимые в CalDAV-профиле, вместе с их URL.
   Найти нужный календарь и скопировать его URL в `CALENDAR_URL` — это
   надёжнее, чем полагаться на поиск по `CALENDAR_NAME`.

## Запуск

Локально:

```bash
python -m src.main
```

В проде — через Docker:

```bash
mkdir -p data && chown 1000:1000 data  # см. примечание ниже
docker compose up -d --build
```

SQLite-файл лежит по пути из `DB_PATH` (локально — `data/reminders.sqlite3`
относительно рабочей директории). В `docker-compose.yml` `DB_PATH`
переопределён на `/data/reminders.sqlite3`, а `./data` смонтирована как том
`/data`, поэтому база переживает пересборку и пересоздание контейнера.

Контейнер работает от непривилегированного пользователя (uid/gid 1000), а не
root. `./data` смонтирована поверх образа как bind mount, поэтому владелец
директории на хосте должен совпадать с этим uid/gid — иначе процесс не сможет
писать в SQLite-файл. Команда выше создаёт директорию и назначает владельца
перед первым запуском.

## Монитор правок и удалений

Помимо напоминалки, бот параллельно ведёт журнал сообщений в том же диалоге:
если собеседник отредактировал или удалил сообщение, владелец подключения
получает уведомление («было → стало» для правки, текст или тип вложения для
удаления). Технически это отдельный слой поверх тех же апдейтов Business API,
он использует общий SQLite-файл (`DB_PATH`), но собственные таблицы
(`owners`, `messages`), и не влияет на логику напоминаний.

Модуль целиком выключается переменной `MONITOR_ENABLED` (см. `.env.example`
— там же остальные настройки монитора: ретеншен, каталог медиа, таймауты).
Скачивание медиафайлов по умолчанию **выключено** для всех типов (фото,
видео, кружки, голосовые, документы) — пишется только текст и метаданные;
включаются типы по отдельности из `/admin`. На сервере действует ретеншен —
сообщения старше 30 дней (настраивается) удаляются суточной задачей вместе с
осиротевшими медиафайлами.

### `/admin`

Команда `/admin` в личном чате с ботом — доступна только `ADMIN_USER_ID`.
Инлайн-меню с экранами:

- **Медиа** — тумблеры скачивания по типам вложений.
- **Хранилище** — размер базы, разбивка по типам медиа, прирост за сегодня /
  неделю / 30 дней.
- **Ретеншен** — текущий срок хранения и его изменение.
- **Мониторинг** — глобальный выключатель, список подключений и их статус.
- **Экспорт** — выгрузка архива документом в чат (текст или текст + медиа),
  с нарезкой на части при превышении лимита Telegram на файл.

### Локальный архив

Сервер хранит только последние 30 дней — полная история живёт локально, на
Mac. `scripts/backup_pull.sh` по SSH (алиас `vps`) забирает
`reminders.sqlite3` и каталог `media/` с сервера и доливает их в локальную
мастер-базу: новые сообщения добавляются через `INSERT OR IGNORE` по
уникальному ключу `(owner_id, chat_id, message_id)`, а для уже
заархивированных подтягиваются только отметки о правке/удалении, если это
случилось после архивации, — сам сохранённый текст не перезаписывается
(это осознанно: правка стирает оригинал, а хранить стоит именно его). Старые
записи не теряются, дубликатов не возникает, поэтому скрипт безопасно
запускать сколько угодно раз. По умолчанию архив лежит в
`~/Archive/tg-reminder-bot` (каталог создаётся скриптом при первом запуске);
свой путь можно передать первым аргументом. Для работы нужен настроенный
SSH-доступ к серверу по ключу (без пароля — агент запускается в фоне, без
терминала для ввода).

Установка еженедельного запуска через `launchd`:

```bash
mkdir -p ~/Library/LaunchAgents
cp scripts/com.nkonshin.reminderbot.backup.plist ~/Library/LaunchAgents/
# заменить REPLACE_WITH_ABSOLUTE_PATH на путь к репозиторию
launchctl load ~/Library/LaunchAgents/com.nkonshin.reminderbot.backup.plist
# разовый прогон для проверки:
./scripts/backup_pull.sh
```

Агент срабатывает по воскресеньям в 03:00; если в этот момент Mac спал,
launchd выполнит пропущенный запуск сразу после пробуждения. Логи — в
`/tmp/reminderbot-backup.log` и `/tmp/reminderbot-backup.err`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

CalDAV-взаимодействие в юнит-тестах не покрывается (только фейками) — его
проверка ручная, см. ниже.

## Проверка боем

После настройки — сквозная проверка на реальных сервисах:

1. С телефона адресата написать в наблюдаемом диалоге:
   «напомни мне через 2 минуты проверить бота».
2. Убедиться, что карточка о созданном напоминании пришла в личный чат с ботом.
3. Убедиться, что в календаре появилось новое событие.
4. Через 2 минуты дождаться пинга с кнопками «Готово» / «Отложить на час».
5. Нажать «Готово» и убедиться, что пинги прекратились.
